# Validation of this delivery

Executed with **GNU Octave 8.4.0** on 2026-10-27. Native MATLAB was not
available in the execution environment. The implementation uses base MATLAB
functions and retains MATLAB `.m` scripts and function files.

## Completed checks

- `run_validation`: passed. This covers duty-cycle timing, one scheduled ON
  device per spatial group, exact centered-grid covering distance, fixed EH
  quanta and arrival statistics, deterministic/probabilistic sensing, action
  failure and capacity clipping, aggregate-information choices, stochastic
  battery-matrix rows, its exact constant-cost limiting distribution, wakeup
  exclusions, common event streams, reproducible seeds, time-averaged energy
  accounting, zero-event cases, archive mode, and Q-reference training.
- Default quick experiment: completed for N=[10,50,100,250], three independent
  deployments per N, four policy families, and 2000 TTIs per deployment.
  All 48 policy/deployment evaluations completed.
- MATLAB MAT and CSV exports: verified. The summary has 16 rows and the raw
  sample export has 48 rows. Saved completion flags and metric counts agree.
- Every quick-run sample satisfies actual drain <= requested drain, actual
  drain <= initial battery/horizon + realized raw harvested input, and stored
  harvest minus actual drain = battery drift. Maximum per-slot network energy
  balance error was **1.20054e-10 normalized energy units**, within floating
  point precision for sums over 250 device batteries.
- Checkpoint restart: passed. A completed experiment resumes with identical
  information samples. A changed physical parameter rejects the checkpoint.
- Event-probability sensitivity pipeline: passed with reduced sample counts
  at alpha=[0.01,0.03,0.1,0.3,1] and N=[10,250]. The smoke test used one
  deployment and 80 TTIs per condition; it verifies execution, not precision.
- Battery Markov demonstration: completed on its 1401-level grid. Maximum
  row-sum error was 1.11e-16 and stationarity residual was 9.94e-12 for the
  explicitly specified fixed action mixture.
- Fifteen quick-run/Markov PNG outputs were generated and checked for valid,
  nonempty image content. Deployment, battery, information, and analytical
  budget examples were visually inspected. The sensitivity plot was also
  generated by its reduced-size pipeline.

The default quick experiment took approximately 35 seconds of measured policy
simulation and 69 seconds of setup/pilot search in this Octave environment,
excluding plot rendering and validation. These are illustrative measurements,
not MATLAB runtime guarantees or reproductions of the paper's hardware study.

## Limits of this validation

The 1000-deployment paper-budget experiment was not run. Published numerical
curves, original trained RL/DT policies, optimality of the heuristics,
and statistical equivalence to the journal experiments were not established.
Three quick-run deployments provide only a functional example. The included
model notes explain the missing source components and model discrepancies.

`output_quick` contains the actual tested example exports. New runs generate
their own values and do not load those exports as inputs.

## RL/DT update: executed checks

The two-stage RL and decision-transformer update was also executed in GNU
Octave 8.4.0 on 2026-10-27.

- `run_validation`: passed after integrating both learning methods.
- `validate_learning`: passed. Both Q tables changed through training,
  learned extra-report actions executed, holdout episodes were excluded from
  training, frozen evaluation preserved all learned tables/weights, repeated
  inference was deterministic, and modified future test events could not
  affect earlier control actions.
- `validate_transformer`: **84 central finite-difference checks** across all
  parameter families passed. Maximum scaled discrepancy was **9.58e-12**.
  The future-token perturbation test passed. Full-network Adam optimization
  reduced a synthetic example loss from **0.704626 to 0.0000058124**; the
  attention projections changed, confirming that attention was trained.
- Return-target tests checked a known discounted-return sequence and verified
  that each token includes previous, rather than current, action/reward.
- `run_rl_dt`: completed with six methods, N=[10,50], two deployments per N,
  400 evaluation TTIs, six RL episodes, and 120 DT updates. It produced 12
  summary rows, 24 evaluation samples, eight saved learned-policy files, and
  18 PNG comparison/system/training figures. Policies were frozen during the
  common-stream evaluation.
- A saved DT policy was reloaded using the guide's deployment-preserving
  workflow. New-stream inference passed the physical budget checks and did
  not change its weights.

The included `output_rl_dt` files contain these actual demonstration results.
The short horizons and sparse extra-report validation samples establish
execution and implementation checks, not learned-policy convergence,
classification generalization, or the rankings in the published figures.
An offline validation loss alone does not establish improved sensing or
energy performance. Full original-model numerical equivalence remains
unverified for the reasons in `MODEL_NOTES.md` and `LEARNING_GUIDE.md`.
